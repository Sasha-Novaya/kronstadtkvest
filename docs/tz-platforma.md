# ТЗ: платформа онлайн-квестов Novik Show

Версия 1 · Oct 26, 2026 · @Sasha Novaya

## Главное за минуту

Платформа — одно мобильное веб-приложение, в которое квесты загружаются как «наборы контента»: новый квест добавляется без новой программы. Первая версия — две реальные станции, доступ по секретной ссылке на 14 дней, сохранение прогресса и простая админ-панель.

При проверке первоисточников нашлись три обстоятельства, которые меняют техническое решение. Их важно увидеть до старта:

1. **Квест должен работать без интернета.** В Петербурге и Ленобласти в 2026 году регулярно отключают мобильный интернет: в такие часы открываются только сайты из «белого списка» ([Фонтанка, 16.10.2026](https://www.fontanka.ru/2026/10/16/76704286/)). Наш сайт в этот список не попадёт. Поэтому при старте приложение скачивает станции маршрута на телефон, а дальше работает и без сети. В первой версии это обязательная функция, а не улучшение «на потом».
2. **Vercel и Supabase из России работают нестабильно, и оплатить их российской картой нельзя.** Пользователи сообщают, что сайты на Vercel со своим доменом у части российских провайдеров не открываются ([форум Vercel](https://community.vercel.com/t/custom-domains-not-working-from-russia/26433)). Supabase и Vercel принимают оплату только зарубежной картой. Бесплатные тарифы не подходят: на Vercel Hobby запрещено коммерческое использование ([документация Vercel](https://vercel.com/docs/plans/hobby)), а бесплатный проект Supabase ставится на паузу после недели без активности.
3. **Скриншоты Яндекс Карт размещать нельзя.** Условия Яндекса прямо запрещают публиковать скриншоты карт ([условия API Яндекс Карт](https://yandex.ru/dev/commercial/doc/ru/)). Картинки карт для станций нужно рисовать самим, а для навигации давать ссылку на Яндекс Карты. Это бесплатно и разрешено.

**Рекомендация.** Оставить предложенную вами логику (React/Next.js, база PostgreSQL, файловое хранилище, GitHub). Но разместить всё у российского облачного провайдера с оплатой в рублях. Пример — Timeweb Cloud: там есть готовое размещение Next.js из GitHub, управляемая база PostgreSQL и хранилище файлов S3. Код пишем так, чтобы его можно было перенести к другому провайдеру без переписывания. Подробное сравнение — в разделе «Архитектура».

### Решения (27.10.2026)

1. **Хостинг** — российский провайдер (Timeweb Cloud или аналог). Vercel и Supabase не используем.
2. **Первые две станции** — из пешего квеста по городу. Тексты пришлёт Саша.
3. **Устройства** — до 3 на одну ссылку.
4. **Подсказки** — на каждое задание 2 подсказки; когда открыты обе, появляется кнопка «Узнать ответ».
5. **Карта** — маленькая карта в углу экрана станции; нажатие открывает точку в приложении Яндекс Карт. Скриншоты Яндекс Карт не используем.
6. **Работа без интернета** — предварительно: запас «на 2 станции вперёд», затем кнопка «Скачать весь маршрут» (этап 4). Окончательно решаем после тестов.
7. **Автовыдача** — заготовку закладываем уже в первую версию (раздел 8).

Остальные детали решены стандартным безопасным способом. Каждое такое решение отмечено в тексте ТЗ.

## 1. Продукт и его функции

Продукт — платформа самостоятельных прогулочных квестов по Кронштадту для семей с детьми от 8 лет и для взрослых. Квест открывается по личной ссылке в браузере телефона, без скачивания из магазина приложений и без регистрации. Капитан Федот Селёдкин и чайка Клуша ведут экипаж от станции к станции: рассказывают историю, загадывают задания, радуются правильным ответам и подсказывают.

Основные функции:

- доступ по уникальной ссылке; 14 суток с момента нажатия «Начать приключение»;
- станции с аудио, текстом рассказа, героями, иллюстрациями, картой и ссылкой на Яндекс Карты;
- задания трёх типов (число, текст, выбор), авторские подсказки и реакции героев;
- сохранение прогресса на сервере и в телефоне, продолжение с другого устройства;
- работа без интернета после загрузки квеста;
- закрытая админ-панель для выдачи и управления ссылками;
- несколько квестов на одной платформе.

## 2. Что из материалов проекта влияет на платформу

В уже принятых сюжетных решениях есть механики, которых нет в технических требованиях. Платформа должна поддерживать их сразу, иначе потом придётся переделывать основу.

| Решение из материалов | Что это требует от платформы | Когда |
| --- | --- | --- |
| «Остров фортов»: после каждого задания в углу экрана дорисовывается часть корабля (корпус, мачты, паруса…); в финале — две чайки на мачте | **Награды станций**: у станции может быть «приз» — картинка-слой, который добавляется в общую коллекцию и показывается в углу экрана | Механизм — в первой версии; рисунки — когда будут готовы |
| Команда придумывает имя корабля; оно звучит в финале и попадает в грамоту | **Задание «Придумать»**: принимается любой непустой ответ; ответ сохраняется в переменную квеста и подставляется в тексты, например «корабль «\[имя\]»» | Первая версия |
| Старт: «Вы уже гуляли с нами по городу?» → разные приветствия | **Вопрос-развилка**: выбор сохраняется в переменную, следующий блок показывается по условию | Первая версия (механизм) |
| «Сегодня понедельник?» → обход музея, станции К-3 и крыши остаются, меняются ориентиры пути | **Варианты блока по условию**: у станции может быть несколько вариантов текста пути; день недели приложение определяет само (московское время), с возможностью уточнить | Механизм — в первой версии |
| Форт «Пётр I» — по желанию; Голландская кухня, Адмиралтейство — «+2 станции, +20 минут» | **Необязательные станции**: экипаж выбирает «Идём / Пропускаем»; пропуск не мешает завершению | Позже |
| Автоквест: «Константин» или «Шанец» на выбор; пауза «Перекусить» со списком кафе | **Ветвление маршрута**: выбор одной из нескольких веток станций; **информационный экран** без задания | Позже |
| Фото «Силачи», «поза пингвина», фото командой у штурвала | **Фото-задание без загрузки**: «Сделали фото? → Дальше»; фото остаётся в галерее телефона, на сервер не отправляется | Первая версия |
| Указатель городов: вписать км с указателя → «Выбран курс на Лондон!» | **Числовое задание с выбором города**: сначала выбор города, затем число, которое проверяется по этому городу | Позже, после фотографий указателя |
| Художественная школа: засчитывается любой ответ с «худож» | **Проверка по корню слова** — как отдельная опция, только когда её явно включил автор | Механизм — в первой версии |
| Аудио до 2 минут; немного иллюстраций — смотреть надо на настоящий город | Плеер и экран станции рассчитаны на 1–3 коротких фрагмента; картинки — только по месту | Первая версия |
| Финал: прощание и приглашение во второй квест | **Финальный экран** с текстом-приглашением и ссылкой на другой квест | Первая версия (простой) |

Эти механики описываются в контенте квеста настройками. Программировать их отдельно для каждого квеста не нужно.

**Решения по сверке (27.10.2026):**

- Вход — только по личной ссылке; ручного ввода кода нет. Экран 0 сценария заменяется приветствием с кнопкой «Начать приключение».
- 14 дней отсчитываются с нажатия «Начать приключение».
- Имена экипажа хранятся на сервере: только имена, без фамилий и контактов.
- Фоновых звуков в тестовой версии нет. Позже они смешиваются с голосом в одном файле, отдельной дорожки в приложении нет.

- Кнопки «Начать заново» нет. При необходимости админ сбрасывает прогресс в карточке ссылки.
- Промокод SELEDKA: в финале показываем промокод и кнопку со ссылкой на страницу покупки «Острова фортов» на агрегаторе.

## 3. Сценарий пользователя

Семья покупает квест заранее, дома открывает ссылку и скачивает маршрут по Wi-Fi, а на острове проходит его без зависимости от сети.

1. **Покупка.** Семья покупает квест на сайте-агрегаторе. Саша создаёт в админ-панели ссылку и отправляет её покупателю. Позже это будет делаться автоматически.
2. **Первое открытие.** По ссылке открывается приветственный экран: обложка квеста, герои, длительность и длина маршрута, советы («зарядите телефон, возьмите наушники, начните там-то»). Отсчёт времени ещё не идёт.
3. **Активация.** Семья нажимает «Начать приключение». Приложение предупреждает: «С этого момента у вас 14 дней». После подтверждения сервер записывает время активации.
4. **Загрузка квеста.** Приложение скачивает станции маршрута на телефон и показывает объём и прогресс. Совет: «Лучше скачать по Wi-Fi дома или в кафе». Можно продолжить и без полной загрузки, тогда материалы подгружаются по ходу.
5. **Старт.** Знакомство с героями и вопросы-развилки («Вы уже гуляли с нами?»).
6. **Путь к станции.** Картинка карты, текстовые ориентиры и кнопка «Открыть в Яндекс Картах». Пешеходный маршрут строится в приложении или на сайте Яндекс Карт. Вернувшись, семья видит тот же экран. Затем нажимает «Мы на месте».
7. **Станция.** Герой рассказывает историю: аудио по кнопке, рядом «Читать историю». Затем задание, подсказки по запросу и реакция героя. После правильного ответа — награда (если есть) и кнопка «Дальше».
8. **Перерыв.** Семья закрывает браузер, обедает, возвращается через час или через три дня, на том же или другом телефоне. Видит экран «Продолжить приключение»: текущая станция, сколько пройдено, сколько дней осталось.
9. **Финал.** Прощание героев, итоги (имя корабля, собранные части), приглашение в другой квест. Позже — именная грамота.
10. **Окончание срока.** Через 14 суток после активации ссылка показывает экран «Срок доступа истёк» с контактом для связи. Защищённые материалы больше не выдаются, скачанные файлы приложение удаляет с телефона.

## 4. Экраны

Для покупателя в первой версии нужно 12 экранов и состояний, для админ-панели — 4. Все экраны покупателя рассчитаны на телефон в вертикальном положении и на чтение на улице: крупный шрифт, контрастные кнопки, кнопки не меньше пальца.

## 6. Архитектура простыми словами

Приложение состоит из пяти частей. Все они используют одни и те же общие компоненты для всех квестов.

| Часть | Что делает (аналогия) | Технология |
| --- | --- | --- |
| **Приложение в телефоне** (фронтенд) | «Витрина»: экраны, плеер, задания. Работает в браузере, хранит копию квеста и прогресса в памяти телефона | React + Next.js |
| **Сервер** (бэкенд) | «Администратор у входа»: проверяет ссылку и срок, выдаёт защищённые файлы, принимает и хранит прогресс. Секретные ключи хранятся только здесь | Тот же проект Next.js (серверная часть) |
| **База данных** | «Журнал регистрации»: ссылки, даты, устройства, прогресс | PostgreSQL |
| **Хранилище файлов** | «Склад»: аудио, иллюстрации, карты. Защищённые файлы выдаются только по временному пропуску от сервера | Хранилище S3 |
| **Контент квеста** | «Сценарий»: тексты, порядок станций, задания, ответы, подсказки — в виде файлов в проекте | Файлы JSON в GitHub; позже — редактор в админке |

**Почему контент в первой версии хранится файлами, а не в базе.** Так проще и надёжнее: Claude Code правит тексты так же, как код, а каждая правка сохраняется в истории GitHub, и её можно откатить. Редактор в админ-панели — это отдельная большая работа. Её стоит делать, когда структура станций устоится на нескольких квестах.

**Почему одна программа, а не отдельная для каждого квеста.** Квест — это папка контента: тексты, картинки, настройки. Плеер, задания, ссылки и прогресс общие. Новый квест = новая папка + запись в базе.

### Где разместить: сравнение

| Критерий | А. Vercel + Supabase (как в требованиях) | Б. Российское облако, например Timeweb Cloud (рекомендую) |
| --- | --- | --- |
| Доступность для туристов в России | Риск: свой домен на Vercel у части провайдеров не открывается; бывают жалобы и на Supabase | Хорошая: серверы в России |
| Оплата | Только зарубежная карта или посредник с комиссией | Рубли, российская карта, СБП |
| Коммерческое использование бесплатно | Нет: Vercel Hobby — только некоммерческие проекты; Supabase Free засыпает после 7 дней без активности | Бесплатных тарифов для этого нет, но минимальные тарифы стоят недорого |

| Простота для новичка | Выше: много готовых инструкций, вход по ссылке Supabase | Немного выше порог: базу и хранилище нужно настроить в панели. Claude Code проведёт по шагам |

Связка Б использует те же технологии, кроме Supabase: вместо него обычная база PostgreSQL и обычное хранилище S3. Для вас разница в том, что вход в админ-панель делает наш сервер, а не Supabase. Это несложно и объясняется пошагово.

Зависимость от одного провайдера минимальна: код работает с любым PostgreSQL и любым хранилищем S3 (Yandex Cloud, Selectel, VK Cloud). Если провайдер не устроит, переезд — это перенос базы и файлов, а не переписывание приложения.

**Схема работы при прогулке.** Телефон один раз получает от сервера «пакет квеста» и пропуска к файлам и скачивает их. Дальше задания проверяются прямо в телефоне, прогресс записывается в телефон и отправляется на сервер, как только появилась сеть. Сеть нужна только для активации, загрузки и синхронизации.

## 8. Ссылки и срок доступа

Ссылка выглядит так: `https://<домен>/q/<секретный код>`. Код — 43 случайных символа (256 бит случайности), угадать его невозможно. Сервер хранит не сам код, а его «отпечаток» (хеш SHA-256). Если базу украдут, рабочих ссылок из неё не получить.

### Как работает ссылка

1. **Создание** (админка): сервер генерирует код криптографически надёжным генератором, сохраняет отпечаток и один раз показывает полную ссылку. Если её потерять, выдаётся новая взамен, старая блокируется.
2. **Открытие**: телефон отправляет код серверу; сервер ищет отпечаток. Нет такого — экран «Ссылка не найдена». Есть — статус и данные квеста.
3. **Активация**: только по нажатию «Начать приключение» и подтверждению. Сервер записывает `активирована = сейчас` и `истекает = сейчас + 14 × 24 часа` по своим часам, а не по часам телефона. Повторное нажатие ничего не меняет: дата активации ставится один раз.
4. **Каждое следующее обращение**: сервер проверяет «не заблокирована и `сейчас < истекает`». Только тогда он выдаёт пропуска к защищённым файлам и принимает прогресс.
5. **Окончание**: после срока сервер отвечает «истекла». Телефон удаляет скачанные материалы и показывает экран «Срок истёк». Прогресс в базе сохраняется: если доступ продлят, семья продолжит с того же места.

**Время.** Сервер хранит время во всемирном формате (UTC). Покупателю показывается московское время: «Доступ до 9 ноября, 14:35».

**Действия админа:** заблокировать (с причиной) и разблокировать; продлить на N дней (к дате окончания добавляется N × 24 ч; если срок уже истёк — отсчёт от текущего момента); сбросить устройства; выдать новую ссылку взамен с переносом прогресса.

### Ограничение передачи ссылки — предлагаемый способ

Семья не должна ничего замечать, а массово раздавать ссылку должно быть бессмысленно. Для этого четыре простые меры:

- **До 3 устройств на ссылку.** При первом открытии телефон получает случайную метку устройства. Её отпечаток сервер записывает в `devices`. Четвёртое устройство видит: «Эта ссылка уже открыта на трёх телефонах. Напишите нам — поможем». Саша может сбросить устройства в админке.
- **Срок 14 дней** сам по себе ограничивает ценность пересылки.
- **Подозрительная активность видна в админке**: много устройств в первый час, обращения из разных городов. Автоматически ничего не блокируется, решение принимает человек.
- **Ограничение частоты запросов**: не более \~30 попыток ввода кода в минуту с одного адреса. Это защита от перебора ссылок.

Не предлагаю привязку к номеру телефона, СМС-коды и вход по e-mail: это усложняет жизнь семье на улице и делает нас оператором персональных данных.

### Автовыдача (позже)

Если агрегатор умеет сообщать о покупке (webhook), сервер получает уведомление, проверяет подпись агрегатора, создаёт ссылку и возвращает её агрегатору или отправляет покупателю. Это отдельный этап: начать с ручной выдачи, затем подключать конкретные агрегаторы по их документации.

**Что закладываем уже в первой версии, чтобы автовыдача подключилась быстро:**

- одна общая функция «создать ссылку» — её вызывает и админка, и будущее подключение агрегатора;
- таблица `orders`: агрегатор, номер заказа, время, созданная ссылка. Номер заказа уникален, поэтому повторное уведомление не создаст вторую ссылку;
- создание пачки ссылок (например 50) с выгрузкой файлом — на случай, если агрегатор умеет выдавать покупателям заранее загруженные коды;
- для каждого агрегатора — свой секретный ключ в настройках сервера, чтобы проверять, что уведомление пришло именно от него.

**Что нужно узнать у каждого агрегатора (без кода):**

1. Умеет ли он сообщать о покупке автоматически (webhook или API)? Если да — попросить документацию для разработчиков.
2. Если нет — можно ли загрузить заранее подготовленные уникальные коды или ссылки, которые он сам выдаёт покупателю?
3. Где покупатель увидит ссылку: в письме агрегатора, в личном кабинете, в ваучере?

## 9. Прогресс, работа без интернета и синхронизация

Главный принцип: прогресс только накапливается и никогда не «откатывается». Пройденная станция остаётся пройденной, решённое задание — решённым. Поэтому записи с разных телефонов всегда можно объединить без потерь.

### Что сохраняется

Текущая станция; пройденные станции; решённые задания и время решения; открытые подсказки; переменные квеста (имя корабля, ответы на развилки); собранные награды; дата завершения. Даты активации и окончания хранит сервер, телефон держит их копию.

### Как сохраняется

1. **Сначала в телефон.** Каждое действие сразу записывается в память браузера (IndexedDB): закрыли вкладку — ничего не потеряно.
2. **Затем на сервер.** Действие ставится в очередь отправки. Если сеть есть, оно уходит через секунду; если нет — когда сеть появится. Каждое событие имеет уникальный номер, поэтому повторная отправка не создаёт дублей.
3. **Сервер объединяет.** Пройденные станции и решённые задания складываются в общее множество, имя корабля берётся по последнему изменению. Текущая станция — самая дальняя по маршруту из пройденных + 1, если экипаж сам не вернулся назад.
4. **Другое устройство.** Открыли ту же ссылку на другом телефоне — сервер отдаёт объединённый прогресс, экран «Продолжить приключение» показывает его.
5. **Два телефона одновременно.** Оба могут работать; при каждой синхронизации каждый получает объединённое состояние. Если на одном телефоне экипаж ушёл дальше, второй предложит: «На другом телефоне вы уже на станции 5. Перейти?»

### Работа без интернета

- **Загрузка маршрута при старте.** После активации телефон скачивает тексты, аудио и картинки всех станций в хранилище браузера. Технически это Service Worker и Cache Storage. Ориентир объёма: 15 станций × \~1,5 МБ ≈ 20–40 МБ.
- **Проверка ответов в телефоне.** Ответы хранятся в виде отпечатков, а не открытым текстом, поэтому их не подсмотреть простым способом. Подробнее — в разделе 10.
- **Срок без сети.** Телефон знает дату окончания с сервера. Если сеть пропала на день, квест продолжает работать до этой даты. Когда сеть появится, сервер подтвердит статус.
- **Яндекс Карты** — внешняя ссылка. Без сети маршрут может не построиться. Поэтому текстовые ориентиры и картинка карты обязательны на каждой станции.
- **Плашка «Нет сети»** честно говорит, что квест продолжается и прогресс сохранится.

**Ограничение iPhone.** Safari может очистить данные сайта, если его не открывали около недели. Если семья вернётся через 10 дней, приложение просто скачает квест заново, а прогресс восстановит с сервера. Чтобы это было надёжнее, на экране «Помощь» предложим «Добавить на экран «Домой»» (позже).

## 10. Проверка ответов и подсказки

Ответ проверяется обычными правилами, без искусственного интеллекта. Ответ человека и каждый допустимый вариант «приводятся к одному виду», а затем сравниваются целиком. Совпадение по части слова засчитывается, только если автор явно включил для задания проверку по корню.

### Шаги «приведения к одному виду» (нормализации)

| Шаг | Пример | Включается |
| --- | --- | --- |
| Без учёта регистра | «КРУЗЕНШТЕРН» = «крузенштерн» | Всегда |
| Лишние пробелы убираются | «  Пётр   Первый » = «пётр первый» | Всегда |
| Знаки препинания, дефисы, тире, кавычки убираются | «Восток-2» = «восток 2», «Ермак!» = «ермак» | По умолчанию да, автор может выключить |
| «ё» = «е» | «Пётр» = «Петр» | По умолчанию да, автор может выключить |
| Число словами = цифрами | «три» = «3», «двадцать один» = «21» | Для числовых заданий по умолчанию да |
| Единицы после числа | «3 якоря» = «3» | Только если включено |
| Римские цифры | «Пётр I» = «Пётр 1» = «Пётр Первый» | Через список вариантов, который задаёт автор |

### Типы заданий

- **Число** — сравнивается число после нормализации; «3.0» = «3». Допуск ± по желанию автора.
- **Текст** — основной ответ + список альтернатив; засчитывается точное совпадение после нормализации с любым из них.
- **Человек** — автор задаёт части имени: обязательную (фамилия) и необязательные (имя, отчество, звание). Засчитывается ответ, где есть фамилия, а остальные слова — только из разрешённых. «Крузенштерн», «Иван Крузенштерн», «адмирал Крузенштерн» — да; «Крузенштерн и Лисянский» — нет.
- **Выбор** — 3–4 варианта, один правильный; порядок вариантов можно перемешивать.
- **Корень слова** (по явному решению автора) — засчитывается ответ, где есть заданный корень, например «худож». Список «запрещённых» слов на этот случай тоже поддерживается.
- **Придумать** — любой непустой ответ (имя корабля); сохраняется в переменную.
- **Фото / действие** — кнопка «Готово».

### Что задаёт автор в каждом задании

Вопрос; тип; основной ответ; альтернативы; правила нормализации (если отличаются от стандартных); реплика героя при правильном ответе; реплика при неправильном (можно несколько, по очереди: первая, вторая, «ещё подумайте»); подсказки по порядку; кнопка «Узнать ответ», которая появляется, когда открыты обе подсказки; награда.

Пример записи задания в контенте (Claude Code будет создавать такие записи из ваших текстов):

```json
{
  "id": "inchkhon-kamni",
  "type": "text",
  "question": "Что в этом сквере выглядит как настоящее, а сделано руками человека?",
  "answer": "камни",
  "alternatives": ["камень", "пластиковые камни", "искусственные камни"],
  "hints": ["Большое, серое, лежит на земле… или притворяется", "Постучите!"],
  "onCorrect": { "hero": "klusha", "text": "…" },
  "onWrong": [{ "hero": "klusha", "text": "…" }],
  "revealAfter": 3
}
```

В готовом пакете, который скачивается на телефон, ответы хранятся не текстом, а отпечатками нормализованных вариантов. Простым просмотром файлов их не прочитать. Для семейного квеста этой защиты достаточно.

### Подсказки

Тексты подсказок пишет только автор, приложение их не придумывает и не меняет. Подсказки открываются по кнопке по одной: «Подсказка 1 из 2». Открытая подсказка остаётся видимой и после перезапуска. Факт использования сохраняется в прогрессе. В первой версии он ни на что не влияет; позже его можно использовать для отметки «без подсказок» в грамоте.

## 11. Аудио, изображения и карты

Каждый файл лежит по предсказуемому адресу «квест / станция / тип / имя», а контент ссылается на него по короткому ключу. Чтобы заменить картинку, достаточно загрузить новый файл с тем же именем — логика приложения не меняется.

### Форматы и сжатие

| Материал | Формат | Размер и качество | Ориентир веса |
| --- | --- | --- | --- |
| Аудио (ElevenLabs) | MP3, моно, 44,1 кГц, 64–96 кбит/с; громкость выровнена у всех фрагментов | До 2 минут на фрагмент | \~1–1,5 МБ на 2 минуты |
| Фото достопримечательностей, исторические фото | WebP | Ширина 1200 px, качество \~75 | до 200 КБ |
| Герои (с прозрачным фоном) | WebP с прозрачностью | Ширина 600–800 px; позы-эмоции отдельными файлами | до 100 КБ |
| Картинки карт | WebP или PNG (если много мелкого текста) | Ширина 1200 px | до 250 КБ |
| Части корабля (награды) | WebP с прозрачностью, одинаковый размер холста для всех частей | 800 × 800 px | до 60 КБ каждая |
| Декор интерфейса, иконки | SVG | — | несколько КБ |

Сжатие делается один раз при подготовке файлов: Claude Code напишет для этого небольшую программу. Вы кладёте исходники в папку, а она создаёт оптимизированные версии. Safari поддерживает WebP с iOS 14, Chrome — давно.

### Где хранится

```
quests/
  ostrov-fortov/
    public/            ← открыто всем: обложка, герои для приветствия, логотип
    stations/
      01-vhod/
        audio/         ← fedot-intro.mp3, klusha-otvet.mp3
        images/        ← mesto.webp, istoriya-1.webp
        map.webp
      02-alleya-petr/
        ...
    rewards/           ← korpus.webp, machty.webp, ...
```

Папка `public` открыта: её содержимое видно на приветственном экране до активации. Всё остальное закрыто и выдаётся по временным пропускам (ссылкам, которые действуют около часа) только для активной ссылки. Имена файлов — латиницей, без пробелов.

### Аудиоплеер

Кнопка «Слушать», пауза и продолжение, перемотка ползунком и «назад на 10 секунд», текущее время и длительность, повтор. Звук включается только нажатием: на iPhone по-другому и нельзя. На станции может быть несколько фрагментов разных героев. Каждый показан карточкой с аватаром и именем, одновременно играет только один. При блокировке экрана звук продолжается, на экране блокировки показывается название фрагмента.

«Читать историю» открывает текст того же эпизода. Текст и аудио хранятся в одном блоке контента, поэтому разойтись не могут. Реплики выделены именем и цветом героя, шрифт крупный (не меньше 17 px).

### Карты

- **Картинка карты** — маленькая карта в углу экрана станции, нажатие открывает точку в приложении Яндекс Карт; сама картинка — собственная схема или значок. Скриншоты Яндекс Карт по их условиям использовать нельзя. Варианты: нарисовать самим или с иллюстратором по своим фотографиям и прогулке; либо сделать на основе OpenStreetMap — его можно использовать бесплатно с подписью «© участники OpenStreetMap».
- **Ссылка на маршрут** строится по координатам точки: `https://yandex.ru/maps/?rtext=~<широта>,<долгота>&rtt=pd`, где `rtt=pd` — пешеходный маршрут ([документация Яндекса](https://yandex.com/dev/yandex-apps-launch-maps/doc/ru/concepts/yandexmaps-web.md)). Пустая начальная точка означает «от моего местоположения». Это нужно проверить на iPhone и Android в тестовой версии. Если Яндекс Карты установлены, обычно открывается приложение, иначе — сайт.
- Ссылка открывается в новой вкладке или в приложении; наша вкладка остаётся на месте, а состояние сохранено в телефоне. При возврате экран тот же.

## 12. Несколько квестов: модель контента

Каждый квест — это папка с одним главным файлом описания и файлами станций. Программа одна. Чтобы выпустить третий квест, не нужно писать код — только подготовить его папку и добавить запись в таблицу `quests`.

### Из чего состоит квест

- **Квест**: код, название, описание и обложка, длительность, тема оформления (цвета, шрифты, фон), список героев, порядок станций, вопросы-развилки на старте, текст финала, приглашение в другой квест.
- **Герой**: код (`fedot`, `klusha`), имя, цвет реплик, набор картинок-эмоций (обычный, радуется, удивлён, думает).
- **Станция**: код, номер, название, блок «Путь» (картинка карты, координаты для Яндекс Карт, текстовые ориентиры, варианты по условию), набор блоков «На месте», награда.
- **Блоки станции**, из которых собирается экран в любом порядке:
  - `story` — эпизод: герой + аудио + текст;
  - `image` — фото или иллюстрация с подписью;
  - `task` — задание (раздел 10);
  - `choice` — вопрос-развилка, сохраняет ответ в переменную;
  - `photo` — фото-задание «Готово»;
  - `info` — просто текст (например, «Здесь можно перекусить»).
- **Условие показа** у любого блока: например «только если `monday = да`» или «только если `walked_before = нет`».
- **Подстановка переменных** в текстах: «Корабль «{shipName}» готов к походу!».

Порядок станций задаётся одним списком в файле квеста: переставили строчки — поменялся маршрут. Тексты станций при этом не трогаются.

### Оформление каждого квеста

Тема квеста — небольшой набор настроек: основной и акцентный цвет, цвет фона, шрифт заголовков, фоновая текстура, форма кнопок. Все экраны берут цвета из темы, поэтому «Остров фортов» и следующий квест могут выглядеть по-разному на одном и том же коде. Дизайн темы первого квеста делаем на этапе 2 по вашим изображениям героев.

### Независимость квестов

Ссылки, прогресс и устройства всегда привязаны к одному квесту. Ссылка «Острова фортов» не открывает пеший квест. Связать квесты можно только приглашением в финале (позже — скидка или промокод).

## 13. Административная панель

Админ-панель — закрытый раздел того же сайта по адресу `/admin`. В первой версии вход только у одного администратора — у вас. Экраны перечислены в разделе 4, здесь — как они работают.

**Вход.** Логин и пароль. Пароль хранится на сервере только в виде отпечатка (алгоритм для паролей, например bcrypt или argon2). После входа браузер получает защищённый «пропуск» (cookie), недоступный для программ на странице. Он действует 12 часов. После 5 неверных попыток вход блокируется на 15 минут. Позже — второй фактор: код из приложения-аутентификатора.

**Список ссылок.** Таблица со столбцами: квест · метка (номер заказа) · статус (не активирована / активна / истекла / заблокирована) · создана · активирована · истекает · пройдено станций (например «5 из 15») · устройств. Фильтры по квесту и статусу, поиск по метке или последним 4 символам кода.

**Создание ссылки.** Квест, метка, комментарий → «Создать». Полная ссылка показывается один раз, с кнопками «Копировать» и «QR-код» (QR удобно отдать на кассе партнёра). Можно создать сразу пачку ссылок, например 20, и выгрузить их файлом для партнёра.

**Карточка ссылки.** Даты, оставшееся время, прогресс по станциям, использованные подсказки, список устройств с датами, журнал действий админа. Кнопки: «Заблокировать» (с причиной) / «Разблокировать», «Продлить на … дней», «Сбросить устройства», «Выдать новую ссылку взамен».

**Позже:** редактор квестов и станций с загрузкой файлов и предпросмотром экрана станции; статистика (продажи по дням, доля дошедших до финала, на какой станции чаще бросают квест, какие задания чаще требуют подсказок); несколько сотрудников с разными правами.

## 14. Безопасность

Все проверки доступа делает сервер. Телефону никогда не доверяем: даже если в нём что-то подменить, сервер не выдаст материалы просроченной или заблокированной ссылке.

| Что защищаем | Мера |
| --- | --- |
| Секретные ключи (база, хранилище, пароль админа) | Хранятся только в настройках сервера («переменные окружения») — не в коде, не в GitHub, не в приложении на телефоне. Файл с ключами для разработки исключён из GitHub |
| Коды ссылок | 256 бит случайности; в базе только отпечаток SHA-256; в журналах сервера код не записывается целиком |
| Утечка кода через адресную строку | Заголовок `Referrer-Policy: no-referrer`: при переходе в Яндекс Карты код ссылки не передаётся чужому сайту |
| База данных | Доступна только серверу (закрытая сеть провайдера или разрешение только с адреса сервера); ежедневные резервные копии |
| Аудио и картинки | Закрытое хранилище; файлы выдаются по временным пропускам (\~1 час) только для активной ссылки. Честно: скачанный файл на телефоне технически можно сохранить; защита не даёт раздавать материалы простыми ссылками |
| Админ-панель | Отдельный вход, отпечаток пароля, защищённый cookie (HttpOnly, Secure, SameSite), блокировка после неверных попыток, журнал действий |
| Подбор и перебор | Ограничение частоты запросов на проверку ссылок, вход в админку и отправку прогресса |
| Подделка запросов | Сервер проверяет, что изменения пришли с нашего сайта; все данные от телефона проверяются по схеме: тип, длина, допустимые значения |
| Соединение | Только HTTPS (бесплатный сертификат у провайдера) |
| Обновления | Раз в месяц — обновление библиотек; Claude Code поможет и проверит, что всё работает |

**Персональные данные.** Платформа не собирает имена, телефоны и e-mail покупателей, а имена экипажа для грамоты остаются в телефоне. Поэтому требования закона 152-ФЗ к нам минимальны. Метка ссылки — номер заказа, а не ФИО. Я не юрист: когда появится автоматическая выдача или продажа напрямую, это стоит проверить у юриста.

**Обязательные тексты на сайте (позже, до продаж):** пользовательское соглашение / условия доступа (срок 14 дней, что входит, возвраты — как у агрегатора) и короткая политика конфиденциальности о том, что хранится в браузере.

## 15. Возможные проблемы и профилактика

| Проблема | Почему возникает | Что делаем |
| --- | --- | --- |
| Нет мобильного интернета на острове или работает только «белый список» | Ограничения связи в Петербурге и области в 2026 году | Загрузка маршрута при старте, проверка ответов в телефоне, очередь отправки прогресса, плашка «Нет сети» |
| Сайт не открывается у части провайдеров | Блокировки зарубежных хостингов | Российский провайдер (вариант Б); перед запуском проверка с разных операторов: МТС, Билайн, МегаФон, Т2 |
| Звук не запускается на iPhone | Safari разрешает звук только после нажатия пользователя | Звук только по кнопке «Слушать»; без автозапуска |
| Два фрагмента играют одновременно | На iPhone играет только один медиапоток | Общий плеер: запуск нового фрагмента ставит на паузу предыдущий |
| После Яндекс Карт вкладка перезагрузилась | Телефон выгрузил вкладку из памяти | Состояние в IndexedDB; при загрузке открываем тот же экран и тот же блок станции |
| Safari очистил данные сайта | Ограничение хранения данных в Safari, если сайт долго не открывали | Прогресс восстанавливается с сервера, квест скачивается заново |
| Режим «Инкогнито» / частный доступ | Данные удаляются при закрытии вкладки | Прогресс всё равно сохранён на сервере; на приветствии подсказка «не используйте режим инкогнито» |
| Неверная дата на телефоне | Часы телефона сбиты | Срок считает только сервер; телефон использует время сервера, полученное при последней связи |
| Мало места на телефоне | Объём квеста 20–40 МБ | Показываем объём заранее; если загрузка не удалась — работаем с подгрузкой по ходу |
| Семья ввела ответ «почти правильно» и застряла | Вариант не предусмотрен | Альтернативы + 2 подсказки + «Узнать ответ»; в журнале событий видны неверные ответы — пополняем список вариантов |
| Ссылку выложили в общий чат | Пересылка | Лимит 3 устройства, блокировка в админке, выдача новой ссылки покупателю |
| Ошибка в коде после обновления | Новая правка что-то сломала | Отдельная тестовая копия сайта; GitHub хранит историю, откат на прошлую версию в один шаг; список проверок перед публикацией |
| Потеря базы | Сбой у провайдера | Ежедневные резервные копии у провайдера + еженедельная выгрузка, которую вы сохраняете у себя |
| Счёт за хостинг вырос неожиданно | Платный трафик | Лёгкие файлы, ограничения расходов в панели провайдера, оповещения о расходах |
| Яндекс Карты открылись без маршрута | Особенности приложения на конкретном телефоне | Проверка ссылок на iPhone и Android на этапе теста; запасной вариант — точка `pt=` без маршрута |

## 16. План разработки по этапам

Каждый этап заканчивается тем, что вы сами открываете результат на своём телефоне и проверяете по списку. Внутри этапа работаем маленькими шагами: одно действие → объяснение → ваша проверка → следующий шаг.

**Как это будет устроено технически.** Код живёт в GitHub. Claude Code вносит изменения прямо туда, в браузере или в приложении для компьютера, — устанавливать программы для разработки вам не придётся. Хостинг сам публикует каждое изменение на тестовый адрес, и вы открываете его на телефоне.

1. **Этап 0. Подготовка** (вы + я, без кода). Регистрация сервисов (раздел 17). Сбор материалов двух станций: тексты, ответы, подсказки, ориентиры, координаты точек, 1–2 картинки героев, черновые аудио, картинки карт.
   - *Проверка:* все аккаунты созданы, материалы лежат в одной папке.
2. **Этап 1. Каркас и публикация.** Пустой проект Next.js в GitHub, автопубликация на хостинге, тестовый адрес открывается на телефоне.
   - *Проверка:* на телефоне открывается страница «Привет, экипаж!».
3. **Этап 2. Экраны квеста на тестовых данных** (без базы и защиты). Тема оформления, экран станции, блоки, плеер, «Читать историю», карта и ссылка на Яндекс Карты, задания, подсказки, реакции героев — на двух реальных станциях.
   - *Проверка:* можно пройти две станции на iPhone и Android; варианты ответов принимаются по таблице проверок.
4. **Этап 3. База данных и ссылки.** Таблицы, создание ссылки (пока через временную служебную страницу), приветствие, активация, проверка срока и блокировки, служебные экраны.
   - *Проверка:* новая ссылка → приветствие → активация → дата окончания через 14 дней; искусственно «состаренная» ссылка показывает «Срок истёк».
5. **Этап 4. Прогресс и офлайн.** Сохранение в телефоне, очередь отправки, объединение на сервере, загрузка маршрута, плашка «Нет сети», лимит устройств.
   - *Проверка:* прошли станцию 1 → закрыли браузер → открыли на другом телефоне → продолжение со станции 2; в авиарежиме станция 2 проходится полностью, прогресс доходит до сервера после включения сети.
6. **Этап 5. Админ-панель.** Вход, список ссылок, создание, карточка, блокировка, продление, сброс устройств, журнал.
   - *Проверка:* все действия из раздела 13 работают; без входа `/admin` не открывается.
7. **Этап 6. Защита и боевой запуск тестовой версии.** Закрытое хранилище файлов и временные пропуска, ограничения частоты, заголовки безопасности, домен, резервные копии.
   - *Проверка:* полный чек-лист раздела 19 на двух телефонах и двух операторах связи.
8. **Этап 7. Остальные станции первого квеста.** Добавляем по 2–3 станции за раз; награды-части корабля, развилки, финал.
9. **Этап 8. Позже.** Грамота, необязательные станции и ветки, второй квест, редактор контента, статистика, автовыдача через агрегаторы.

Этапы 1–6 — это тестовая версия с двумя станциями. Сроки зависят от того, сколько времени вы готовы уделять проверкам. Ориентир — несколько недель при работе по 1–2 часа в день. Назову его точнее после этапа 1, когда будет понятен темп.

## 19. Критерии готовности тестовой версии

Тестовая версия готова, когда все пункты ниже выполнены на iPhone (Safari) и на Android (Chrome), с двух разных операторов связи. Отмечайте галочками прямо здесь.

**Ссылка и доступ**

- [ ] Новая ссылка из админки открывает приветствие; отсчёт не начался (в админке «не активирована»)
- [ ] «Начать приключение» → подтверждение → в админке дата активации и окончания ровно через 14 × 24 ч
- [ ] Повторное открытие ссылки не сдвигает дату активации
- [ ] Неверный код → «Ссылка не найдена»; заблокированная → «Ссылка заблокирована»
- [ ] Ссылка с искусственно истёкшим сроком → «Срок истёк», защищённые файлы не открываются даже по прямому адресу
- [ ] Продление в админке снова открывает доступ, прогресс на месте
- [ ] Четвёртое устройство видит сообщение о лимите; после сброса устройств — открывается

**Станции**

- [ ] Герои, иллюстрации и картинка карты отображаются; вес каждой картинки — в пределах таблицы раздела 11
- [ ] Аудио: запуск, пауза, продолжение, перемотка, повтор, длительность; звук идёт при заблокированном экране
- [ ] «Читать историю» показывает текст того же эпизода, текст удобно читать
- [ ] Нажатие на карту открывает Яндекс Карты с пешеходным маршрутом к точке; после возврата экран тот же
- [ ] Задания всех использованных типов работают; принимаются все варианты из списка проверок, отклоняются заведомо неверные (список проверок составляем вместе на этапе 2)
- [ ] Подсказки открываются по одной, остаются после перезапуска; «Узнать ответ» появляется после второй подсказки
- [ ] Реакции героев на правильный и неправильный ответ показываются

**Прогресс**

- [ ] Пройти станцию 1 → закрыть браузер → открыть снова: «Продолжить приключение», станция 2, оставшееся время
- [ ] Открыть ту же ссылку на втором телефоне — тот же прогресс
- [ ] Включить авиарежим после загрузки: станция 2 полностью проходится; после включения сети прогресс виден в админке
- [ ] Прогресс не теряется при одновременной работе двух телефонов

**Админ-панель и безопасность**

- [ ] `/admin` без входа не открывается; после 5 неверных паролей вход временно блокируется
- [ ] Список, создание, карточка, блокировка, продление, сброс устройств работают; действия видны в журнале
- [ ] В коде на GitHub и в приложении на телефоне нет секретных ключей (проверяем поиском)
- [ ] Сайт открывается без VPN у МТС, Билайна, МегаФона или Т2 и по Wi-Fi

## 20. Словарик терминов

| Термин | Простыми словами |
| --- | --- |
| Веб-приложение | Сайт, который ведёт себя как приложение: открывается по ссылке в браузере |
| Фронтенд / бэкенд | То, что видно в телефоне / то, что работает на сервере и скрыто от пользователя |
| Сервер | Компьютер в дата-центре, который круглосуточно отвечает на запросы телефонов |
| Хостинг / провайдер | Компания, которая сдаёт в аренду серверы и место для сайта |
| React, Next.js | Популярные «конструкторы» для создания веб-приложений; Next.js объединяет экраны и сервер в одном проекте |
| База данных, PostgreSQL | Надёжная «таблица Excel» на сервере для многих пользователей сразу; PostgreSQL — самая распространённая бесплатная база |
| Хранилище S3 | «Облачный склад» для файлов: аудио, картинок. S3 — общепринятый стандарт, его поддерживают многие провайдеры |
| GitHub, репозиторий | Онлайн-хранилище кода с историей всех изменений; репозиторий — папка одного проекта |
| Деплой (публикация) | Выкладка новой версии приложения на сервер |
| Домен | Адрес сайта, например `kvest.ru` |
| HTTPS | Защищённое соединение (замочек в адресной строке) |
| Токен / секретный код ссылки | Длинная случайная строка в ссылке, которая работает как ключ |
| Хеш (отпечаток) | Необратимое «зашифрованное» представление строки: по нему можно проверить код, но нельзя восстановить |
| Cookie | Маленькая записка, которую сайт оставляет в браузере, например «администратор вошёл» |
| Переменные окружения | Секретные настройки сервера (пароли, ключи), которые хранятся отдельно от кода |
| Webhook | Автоматическое уведомление от другого сервиса: «здесь купили квест» |
| API | Способ, которым программы обмениваются данными друг с другом |
| IndexedDB, Cache Storage, Service Worker | Встроенные в браузер «шкафчики» и «помощник», которые хранят квест и прогресс в телефоне и позволяют работать без интернета |
| Синхронизация | Сведение данных телефона и сервера к одному состоянию |
| Нормализация ответа | Приведение ответа к единому виду перед сравнением: без регистра, лишних пробелов, «ё» → «е» |
| JSON | Простой текстовый формат для записи данных: тексты станций, задания, ответы |
| SSR | Режим, при котором сервер сам собирает страницу перед отправкой в телефон |
| 152-ФЗ | Российский закон о персональных данных |
