# Правила проекта «Аудиоквесты по Кронштадту»

Мобильное веб-приложение — платформа аудиоквестов по Кронштадту.
Герои: капитан Федот Селёдкин и чайка Клуша. На платформе будет несколько квестов.

## Главные источники — техническое задание (ТЗ)

- `docs/tz-platforma.md` — ТЗ платформы: архитектура и решения.
  Разделы «Решения» и «Решения по сверке» важнее остального текста этого файла.
- `docs/tz-stancii-1-2.md` — ТЗ старта и станций 1–2: тексты, экраны и задания.
  При расхождении текстов главный — этот файл.
- Файлы ТЗ не редактировать без прямой просьбы Саши.

## Что делаем сейчас

- Работаем по плану этапов из раздела 16 ТЗ платформы. Не забегать вперёд:
  делаем только текущий этап.
- Платформа рассчитана на несколько квестов, но сейчас делаем и проверяем только
  один: пеший квест по городу Кронштадт (код квеста `kronstadt-walk`).
  Остальные квесты не добавлять.

## Ничего не придумывать

- Сюжет, тексты, реплики героев, задания, ответы, подсказки и названия
  ничего не придумывать — брать только из ТЗ.
- Если чего-то нет в ТЗ — спросить Сашу.

## Как общаться с Сашей

- Всегда по-русски, простыми словами.
- Саша не программист: каждый технический термин объяснять при первом упоминании
  (например: «репозиторий — это папка проекта с историей изменений»).
- В конце каждой задачи коротко рассказывать: что сделано, какие файлы изменились,
  что Саше нужно сделать дальше.
- Всегда присылать Саше готовые полные ссылки — она не должна ничего искать сама:
  на страницы сайта (тестовый адрес + путь, например `/dev/assets`), на файлы и папки
  в GitHub (`https://github.com/Sasha-Novaya/kronstadtkvest/...`), на pull request.
  Если что-то можно показать только снимком экрана — прислать снимок.
- Тестовый адрес сайта на Timeweb: пока не известен (Саша пришлёт — записать сюда).

## Как работать

- Маленькими шагами: одна задача — одно небольшое понятное изменение.
- Перед отправкой изменений проверять, что проект собирается: `npm run build`
  и `npm run lint`.
- Не добавлять лишних библиотек без необходимости и без объяснения, зачем они.

## Секреты и безопасность

- Никогда не записывать пароли, ключи, токены и другие секреты в код и в GitHub.
- Секреты хранятся только в переменных окружения:
  - на компьютере — в файле `.env.local` (он в `.gitignore` и не попадает в GitHub);
  - на хостинге — в настройках переменных окружения Timeweb Cloud.
- В `.env.example` можно писать только названия переменных, без значений.

## Технологии и инфраструктура

- Фреймворк: Next.js (App Router, TypeScript), Node.js 22.
- Хостинг: Timeweb Cloud (App Platform), Next.js с включённым SSR.
  Хостинг собирает и запускает так: `npm install` → `npm run build` → `npm start`
  (`next start`, порт из переменной окружения `PORT`). `output: "standalone"` не используем.
- База данных: PostgreSQL (в Timeweb Cloud).
- Файлы (аудио, картинки): S3-хранилище (в Timeweb Cloud).
- Vercel и Supabase НЕ используем.

## Персональные данные

- Персональные данные покупателей не собираем.
- Единственное исключение — имена участников экипажа, чтобы напечатать их в грамоте.
  По «Решениям по сверке» ТЗ платформы они хранятся на сервере: только имена,
  без фамилий и контактов.
